# Breakdown

Use the accepted source as the boundary of the work. Follow the user's output format and the project's tracker or planning conventions when present.

Prefer tracer bullets: each slice produces an observable outcome through every necessary layer. Merge fragments that are useful only together; avoid tickets organized solely by frontend, backend, schema, or tests.

For each slice, make clear:

- the outcome and included scope;
- observable acceptance evidence;
- dependencies or ordering constraints;
- unresolved decisions that block implementation.

Estimate only when requested or when the project requires it.

Complete when every requirement is covered, no acceptance condition is orphaned, and each slice can be delivered and verified independently.
