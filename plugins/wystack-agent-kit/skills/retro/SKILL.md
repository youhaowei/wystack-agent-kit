# Retro

Use actual evidence: planned scope, commits, reviews, incidents, verification, estimates, lead time, and user outcomes. Follow the user's format or the project's retrospective convention.

Look for repeatable patterns rather than narrating events. For each material pattern, connect:

- evidence;
- impact;
- likely cause;
- the smallest change that addresses it;
- how the change will be evaluated.

Distinguish process problems from one-off noise. Keep what worked as deliberately as what should change. Treat workflow or policy changes as proposals until the user accepts them.

Complete when the retrospective produces a few owned, measurable adjustments—or evidence that no adjustment is warranted.
