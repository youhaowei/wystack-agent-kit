# Brainstorm lenses

Use a lens only when it reveals a decision the general brainstorm would miss.

## Product

Clarify the user, current workaround, desired change, evidence of demand, and smallest outcome worth shipping. Test whether the proposed feature is the only way to create that outcome.

## Architecture

Map ownership, boundaries, invariants, failure modes, reversibility, and the strongest competing shape. Prefer the smallest design that preserves the required future options.

## Domain

Compare the idea with existing domain terms, rules, and scenarios. Resolve names that hide different concepts; use edge cases to expose unclear boundaries. Update canonical artifacts only after the meaning is accepted.

## Builder

When the goal is exploration or learning, optimize for the smallest exciting experiment. Separate what must be real from what can be simulated, and define what the experiment should teach.

## Reduction

Ask what can be removed without losing the core outcome. Split “must ship together” from “nice to ship together,” and make the cost of each retained element visible.
