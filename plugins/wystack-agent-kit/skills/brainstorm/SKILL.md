# Brainstorm

Turn ambiguity into a decision.

- Investigate what the codebase, existing artifacts, and evidence can answer before asking the user.
- Focus discussion on the weakest of: goal, constraints, success criteria, and context.
- Ask only questions whose answers can change the design. Match the pace and grouping to the user.
- Present materially different approaches when a real choice exists. Recommend one and make the trade-off visible.
- Keep scope and unresolved decisions explicit.

Use [FRAMEWORKS.md](FRAMEWORKS.md) only when a domain-specific lens would improve the discussion.

Complete when the user can accept a direction, see the rejected alternatives, and identify any remaining decision or evidence gap. Continue into implementation only when the user chooses to.
