# UX Writing

Optimize for task completion, not persuasion. Use the project's voice and canonical domain terms.

Write labels that predict the action, errors that explain recovery, empty states that offer a useful next step, and system feedback that tells the user what changed. Fit the language to the actual interface constraints and state; copy detached from the flow is incomplete.

Check clarity in context, including accessibility names and destructive or irreversible actions. Prefer concrete language over personality when they conflict.

Complete when the user can understand the current state, available action, and consequence without relying on visual position or implementation knowledge.
